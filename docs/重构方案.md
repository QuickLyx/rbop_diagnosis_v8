# v8 重构方案（不影响正在运行的阶段三实验）

## 0. 硬约束：为什么必须隔离

`scripts/run_stage3.sh --execute` 每一格都重新启动 `python train.py / evaluate.py / shallow.py ...`，
**每格启动时读取的是工作目录里当前的源码**。因此：

- 在 `rbop_diagnosis_v8/` 工作目录里改任何 `.py`，后续格就会用新代码跑，同一矩阵前后口径不一致。
- 改 `scripts/run_stage3.sh` 本身更危险：bash 边执行边读脚本，改动可能让正在运行的循环错位。
- 在该目录执行 `git checkout` / `git switch` / `git stash` 同样会改写文件。

规则：**实验结束前，主工作目录只允许新增文档，不改、不切换任何代码文件。** 重构全部在独立 worktree 进行。

## 1. 隔离方式（R0，约 5 分钟）

```bash
cd rbop_diagnosis_v8
git worktree add ../rbop_diagnosis_v8_refactor -b refactor
```

- worktree 是另一个目录，`ROOT = Path(__file__).parent` 指向新目录，其 `outputs/` 为空，不会写入真实产物。
- 在 worktree 里**禁止**运行任何 `--execute`；只运行单测与 `--dry-run`。
- `outputs/` 被 `.gitignore` 忽略，其中的 `.py` 不在仓库中，R1 需手工复制进 worktree。

## 2. 等价性验证（每个阶段结束都跑）

重构只改结构，不改行为。三层检查，全部零训练：

1. 全量单测：`"$PYTHON" -m unittest discover -s tests -v`，数量与通过数和重构前一致（当前 137 项）。
2. preflight 输出比对：分别在主目录（只读）与 worktree 跑 `bash scripts/run_stage3.sh`（不带 `--execute`），
   输出逐字 `diff` 为空。路径字段若因根目录不同而不同，先把根目录前缀替换掉再比。
3. 单格评估比对（实验结束后做，避免与训练抢 GPU）：对一个已完成格的 `last.pt`，
   用新旧代码各跑一次 `evaluate.py --output <临时目录>`，`predictions.csv`、`unit_predictions.csv`、`metrics.json` 逐字节一致。

任何一层不一致：回退该阶段，不修改测试去迁就新代码。

## 3. 重构阶段（按收益排序）

| 阶段 | 内容 | 预计耗时 |
|---|---|---|
| R1 | 产物目录里的脚本迁到 `scripts/analysis/` | 20 分钟 |
| R2 | 拆五个超长函数 | 半天 |
| R3 | 跨模块使用的私有函数改为公开名 | 1 小时 |
| R4 | 测试注入参数显式化 | 30 分钟 |
| R5 | v1/v2 状态标注 + README 缩写表 | 30 分钟 |

### R1 迁移脚本

- `outputs/analysis_ies_diag/diag_*.py`、`outputs/P2_logs/verify_P2_P3.py` → `scripts/analysis/`。
- 修正脚本内的相对路径与 `sys.path` 处理，使其与 `scripts/` 下现有脚本写法一致。
- 原位置的副本在实验结束后再删除（它们是历史产物的生成脚本，删前确认已入库）。

### R2 拆超长函数

只按函数内部已有的步骤切分，不新增类、不新增模块（遵守 `agents.md`"不建抽象层"）。拆出的函数放在原文件内、紧邻原函数。

| 函数 | 现状 | 拆分 |
|---|---|---|
| `evaluate._run_fusion` | 153 行，无 docstring | 参数校验 / dry-run 依赖报告 / 读三路证据并选权重 / PU 记录对齐 / 落盘 |
| `transfer.train_model` | 155 行，11 参数 | 采样器构造 / 单轮训练 / 每轮落盘；参数列表不改 |
| `train.prepare_plan` | 133 行 | 每类臂的依赖检查各成一个函数 |
| `features.build_cache` | 116 行 | 枚举记录 / 逐记录提特征 / 写缓存与版本 |
| `shallow.fit_shallow` | 101 行，无 docstring | 采样 / 候选搜索 / 校准与落盘 |

要求：公开函数签名与返回值不变；校验与 `raise` 原样保留，不合并、不放宽；补 docstring。

### R3 私有函数公开化

`features_v2.py` 与 `scripts/*.py` 从 `features` 导入了 `_record_signal_12k`、`_bandpass_envelope`、
`_geometry_for`、`_real_signal`、`_validate_rotation` 等私有函数。去掉下划线前缀，
并用 `grep -rn` 一次改完所有调用点（含 `tests/`）。不保留旧名别名。

### R4 测试注入显式化

`evaluate.py` 中 `getattr(args, "deep_eval_root", None)`、`getattr(args, "normal_root", None)`
改为 `build_parser` 里声明的参数（默认 `None`，help 注明"仅测试使用"），测试改为传参。

### R5 文档

- `features_v2.py`、`physical_baseline_v2.py`、`scripts/evaluate_v2.py` 文件头首行写明"探索性，不替换 v1 正式口径"。
- `README.md` 增加缩写表：E1、E2、P_ball、K19/K19_gg/K116、q_phys、IES、PU、CW、GG、RS。

## 4. 明确不做

- 不拆分 `evaluate.py` 为多个模块：`agents.md` 禁止按概念另建模块；改为在文件内用分节注释排列深度/融合/物理三段。
- 不合并 v1/v2：v1 是冻结正式口径，合并会改变已落盘结果的可复现路径。
- 不改 `configs/stage3.json`、判据、池、臂清单、`run_stage3.sh`。

## 5. 合并时机

1. 确认 `run_stage3.sh --execute` 进程已退出，日志末行为"正式顺序执行完成"。
2. 在 worktree 完成第 2 节三层验证。
3. 主目录 `git merge refactor`，再跑一次全量单测。
4. 若需 `_retry1` 重跑某格：**用重构前的提交跑**（`git worktree add ../v8_frozen 4dd221a`），保证同一矩阵代码一致。
